## 1. 모듈 개요

### 담당 범위

PM3는 시스템의 **운영 기반(Infrastructure) 5개 모듈**을 담당합니다. 이 모듈들은 AI 기능 모듈(숙성발효관리, 원재료관리, 포장출하관리)이 올바르게 동작하기 위한 데이터 품질, 공정 기록, KPI 측정, 기준값 관리, 시스템 운영의 기반을 제공합니다.

| # | 모듈명 | 역할 | 주요 사용자 |
|---|--------|------|------------|
| 1 | 공정관리 | 전 공정 실적 기록, 레시피 관리, 이상 감지 | 공장장, 현장 작업자 |
| 2 | 데이터관리 | 데이터 파이프라인 운영, AI 학습 데이터 관리 | 관리자, 데이터 담당자 |
| 3 | KPI관리 | 생산성·품질 KPI 계산 및 리포트 | 공장장, 관리자 |
| 4 | 기준정보관리 | 품질·공정 기준값, SOP, 코드 체계 | 품질 담당자, 관리자 |
| 5 | 사용자/시스템관리 | 권한, 로그, 알림, 시스템 설정 | 관리자(Admin) |

## 2. 모듈별 기능 구조 (3단계 메뉴 트리)

### 2.1 공정관리

```
공정관리 (Level 1)
├── 공정실적관리 (Level 2)
│   ├── 입고/보관 실적 입력 (Level 3)
│   ├── 절단/전처리 실적 입력
│   ├── 세척/절임 실적 입력
│   ├── 세척/선별 실적 입력
│   ├── 탈수 실적 입력
│   ├── 혼합 실적 입력
│   ├── 숙성/발효 실적 입력
│   ├── 금속검출 실적 입력
│   └── 포장/출하 실적 입력
├── 공정 데이터 모니터링 (Level 2)
│   ├── 실시간 공정 현황판
│   ├── 센서 데이터 실시간 조회
│   └── 공정별 이상 알림 현황
├── 레시피 관리 (Level 2)
│   ├── 제품별 레시피 조회
│   ├── 레시피 등록/수정
│   └── 레시피 이력 조회
├── 공정이력조회 (Level 2)
│   ├── LOT별 공정이력 조회
│   ├── 날짜별 공정이력 조회
│   └── 공정별 이력 조회
└── 공정데이터 분석 (Level 2)
    ├── 공정별 생산량 분석
    ├── 공정 불량률 분석
    └── 공정 소요시간 분석
```

### 2.2 데이터관리

```
데이터관리 (Level 1)
├── 데이터통합관리 (Level 2)
│   ├── 파이프라인 상태 모니터링
│   ├── Edge Collector 연결 상태
│   └── ETL 작업 현황 및 로그
├── 데이터조회 (Level 2)
│   ├── 정형 데이터 조회 (PostgreSQL)
│   ├── 센서 시계열 데이터 조회
│   └── LOT 통합 데이터 조회
├── 데이터시각화 (Level 2)
│   ├── 시계열 차트
│   ├── 공정별 산포도
│   └── 상관관계 분석 차트
├── 데이터다운로드 (Level 2)
│   ├── Excel 다운로드
│   ├── CSV 다운로드
│   └── JSON 다운로드
└── AI학습 데이터관리 (Level 2)
    ├── 학습 데이터셋 조회
    ├── 라벨링 관리
    └── 데이터 품질 검증
```

### 2.3 KPI관리

```
KPI관리 (Level 1)
├── 생산성 KPI 조회 (Level 2)
│   ├── 시간당 생산량 현황
│   ├── 생산량 트렌드 분석
│   └── 목표 대비 실적 비교
├── 품질 KPI 조회 (Level 2)
│   ├── 완제품 불량률 현황
│   ├── 불량률 트렌드 분석
│   └── 공정별 불량 현황
└── KPI 관리 (Level 2)
    ├── KPI 목표값 설정
    ├── KPI 알림 임계값 설정
    └── KPI 리포트 생성
```

### 2.4 기준정보관리

```
기준정보관리 (Level 1)
├── 품질기준 관리 (Level 2)
│   ├── 절임 공정 품질 기준
│   ├── 발효 공정 품질 기준
│   └── 출하 품질 기준
├── 작업표준 관리 (Level 2)
│   ├── SOP 문서 조회
│   ├── SOP 업로드 및 Vector DB 연동
│   └── SOP 이력 관리
└── 코드관리 (Level 2)
    ├── 공정 코드 관리
    ├── 제품 코드 관리
    ├── 불량 코드 관리
    └── 기타 코드 관리
```

### 2.5 사용자/시스템관리

```
사용자/시스템관리 (Level 1)
├── 사용자 관리 (Level 2)
│   ├── 사용자 목록 조회
│   ├── 사용자 등록/수정/삭제
│   └── 역할(Role) 관리
├── 로그 관리 (Level 2)
│   ├── 시스템 로그 조회
│   ├── 사용자 활동 로그 조회
│   └── AI Agent 질의 로그 조회
├── 알림 설정 (Level 2)
│   ├── 알림 채널 설정 (SMS/Email/Push)
│   ├── 알림 수신자 설정
│   └── 알림 이력 조회
└── 시스템 설정 (Level 2)
    ├── Edge Collector 연결 설정
    ├── 센서 매핑 설정
    └── 배치 스케줄 설정
```

## 6. KPI 관리 상세 명세

### 6.1 KPI 계산 공식 명세

#### 생산성 KPI: 시간당 생산량 (kg/h)

```
시간당 생산량 = 월 포장 완료 수량 (kg) / (월 생산일수 × 일 근무시간)

세부 계산:
- 월 포장 완료 수량: 포장/출하 공정의 월간 합격 포장 수량 합계
- 월 생산일수: 해당 월 실제 생산 작업일 수 (휴일 제외)
- 일 근무시간: 기준정보에서 설정된 일 근무시간 (기본값: 8시간)

측정 주기: 월별 기준 (일별 추이 모니터링 병행)
기준년도: 2025년 11월~1월 (3개월 평균 = 2,750 kg/h)
목표: 3,000 kg/h (2026년 12월 기준)
```

#### 품질 KPI: 완제품 불량률 (%)

```
완제품 불량률 (%) = (불량 수량 (kg) / 총 생산 수량 (kg)) × 100

세부 계산:
- 불량 수량: 포장 공정 중량 불량 수량 + 출하 전 품질 검사 불합격 수량
- 총 생산 수량: 포장 완료 총 수량 (합격 + 불량)

측정 주기: 일별 (월별 집계 KPI)
기준: 2025년 평균 1.5% (시간당 약 41 kg 불량)
목표: 1.0% (시간당 약 30 kg 불량, -26.8%)
```

#### 보조 KPI 항목

| KPI명 | 계산식 | 목표값 | 측정 주기 |
|-------|--------|--------|----------|
| 발효 품질 예측 정확도 | AI 예측 정확도 (분류) | >= 80% | 주별 |
| 발효 완료 시점 예측 오차 | MAE (시간) | <= 2시간 | LOT별 |
| 이상 발효 조기탐지 정확도 | Recall | >= 85% | 월별 |
| 원재료 불합격률 | 불합격 입고수/총 입고수 × 100 | <= 5% | 월별 |
| LOT 추적가능성 | 추적 성공 LOT / 전체 LOT × 100 | 100% | 상시 |
| Edge Collector 가동률 | 정상 운영 시간 / 전체 시간 × 100 | >= 99% | 월별 |

### 7.2 작업표준서(SOP) 업로드 및 Vector DB 연동 프로세스

#### SOP 업로드 프로세스

```
Step 1: 파일 업로드 (화면 B-05)
    - 지원 형식: PDF, DOCX, XLSX, HWP
    - 최대 파일 크기: 50MB
    - 파일명 규칙: [공정코드]_[문서유형]_[버전]_[YYYYMMDD].pdf
      예: PROC03_SOP_v1.2_20260101.pdf

Step 2: 메타데이터 입력
    - 문서 유형: SOP / 품질기준서 / HACCP / 설비매뉴얼 / 클레임대응
    - 해당 공정 코드: 다중 선택 가능
    - 문서 제목, 버전, 유효기간
    - 작성자, 검토자, 승인자

Step 3: 임베딩 처리 (자동)
    - 문서 텍스트 추출 (PDF → text, DOCX → text)
    - Chunking: 문단 단위 (최대 1,000 토큰, 200 토큰 overlap)
    - 임베딩 모델 적용 (text-embedding-ada-002 또는 동급)
    - pgvector에 저장 (문서 ID + chunk index + vector)

Step 4: 검증 및 활성화
    - 임베딩 완료 확인 (chunk 수, 처리 시간 표시)
    - 관리자 검토 후 활성화 (is_active = true)
    - 구 버전 문서 비활성화

Step 5: AI Agent 연동 확인
    - 샘플 질의 테스트: "절임 공정 표준 염도는?"
    - 응답에 업로드 문서 내용 포함 여부 확인
```

#### 시스템 로그 테이블 스키마

```sql
CREATE TABLE system_log (
    log_id      BIGSERIAL PRIMARY KEY,
    log_level   VARCHAR(10) NOT NULL,       -- ERROR/WARNING/INFO/DEBUG
    log_time    TIMESTAMP NOT NULL DEFAULT NOW(),
    module      VARCHAR(50),                -- 발생 모듈
    message     TEXT NOT NULL,
    stack_trace TEXT,                       -- 오류시 스택 트레이스
    server_id   VARCHAR(20)                 -- 발생 서버 ID
);
CREATE INDEX idx_system_log_time ON system_log(log_time DESC);
CREATE INDEX idx_system_log_level ON system_log(log_level);
```

#### 사용자 활동 로그 (S-05)

```sql
CREATE TABLE user_activity_log (
    log_id      BIGSERIAL PRIMARY KEY,
    user_id     VARCHAR(20) NOT NULL,
    log_time    TIMESTAMP NOT NULL DEFAULT NOW(),
    action      VARCHAR(50) NOT NULL,       -- LOGIN/LOGOUT/CREATE/UPDATE/DELETE/VIEW/DOWNLOAD
    resource    VARCHAR(100),               -- 접근한 메뉴/화면
    resource_id VARCHAR(50),                -- 대상 리소스 ID (LOT ID, 사용자 ID 등)
    ip_address  VARCHAR(45),
    user_agent  VARCHAR(200),
    result      VARCHAR(10)                 -- SUCCESS/FAIL
);
```

## 부록: 화면 레이아웃 가이드

### Streamlit 레이아웃 원칙

1. **좌측 사이드바**: 메뉴 네비게이션 (역할에 따라 메뉴 필터링)
2. **상단 헤더**: 현재 위치(Breadcrumb), 사용자명, 로그아웃
3. **주요 콘텐츠 영역**: 화면 유형에 따라 구성
   - Form 화면: 2열 레이아웃 (라벨 + 입력 필드)
   - Table 화면: 필터 영역 + 데이터 테이블 + 페이지네이션
   - Dashboard 화면: 카드 + 차트 그리드
4. **알림 배너**: 상단 고정, 미처리 Critical 알림 건수 표시

### SmartPad 화면 원칙

1. **터치 최적화**: 버튼 최소 크기 48×48px
2. **핵심 입력만 표시**: 공정 실적 입력 항목 최소화 (필수 항목만)
3. **자동 채번**: LOT ID 자동 생성으로 입력 오류 최소화
4. **오프라인 모드**: 네트워크 불안정 시 로컬 임시 저장 후 동기화
5. **글자 크기**: 최소 16px (공장 환경 가독성)
