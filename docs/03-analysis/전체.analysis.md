## 세부 분석

### 1. 애플리케이션 모듈 (100%)

- **10개 전 모듈** DB·API·UI 3계층 완성
- API 엔드포인트 총 121개 (dashboard 9 + material 14 + fermentation 18 + shipping 22 + process 14 + data 16 + agent 14 + master 7 + system 11 + kpi 8 + approval 9)
- UI: 10개 메인 페이지 + Shadow Mode 승인 전용 페이지
- 설계 추가 기능 3건 (DQ 검사, Edge 매핑, AI 사용량) 포함

### 2. AI 모듈 (98%)

**ML Engine (`ml/`)**
- 설계 6개 모델 전부 구현: XGBoost(품질분류), RandomForest(SHAP 연계), SVR(산도/숙성도 회귀), LSTM(완료시점, Sliding Window), SHAPExplainer, AnomalyDetector(IsolationForest+XGBoost), QualityEnsemble(소프트보팅)
- KPI 성능 목표 코드화: `TARGETS` dict + `evaluate()`의 `target_*_met` 게이트
  - 품질예측 정확도 ≥ 80%
  - 이상탐지 정확도 ≥ 85%
  - 발효완료 예측 MAE ≤ 2시간
  - 회귀 R² ≥ 0.85
- 합성 데이터 생성기: `--synthetic` (3개월 LOT 미축적 기간 대응, 500 LOT × 24h)
- Gap: Prophet 추세 예측 코드 미확인 (requirements 포함, 영향 낮음)

**RAG Agent (`rag/`)**
- INTAKE / SHIPPING / INTEGRATED 3종 실연동 완료
- `_rag_stub` 완전 제거 → `rag.agent_router.run_rag_agent()` 교체 확인
- LangGraph StateGraph + ReAct 루프 (최대 5회 tool call)
- pgvector 코사인 검색 (`embedding <=> query::vector`, score_threshold 환각 방지)
- 내부 예외 흡수 (API 502 미전파)

### 3. 인프라 (95%)

**DB 초기화 (`db_init.sql`)**
- 11단계 의존성 순서: 기준정보→시스템→공정→원재료→발효→출하→데이터→KPI→Agent→대시보드VIEW→승인
- 멱등 설계: `IF NOT EXISTS` / `ON CONFLICT` / `ALTER TABLE ADD COLUMN IF NOT EXISTS`
- `\set ON_ERROR_STOP on` 오류 발생 시 즉시 중단

**Docker Compose**
- 4개 서비스: db(5432) + vector-db(5433, pgvector/pgvector:pg15) + api(8000) + ui(8501)
- healthcheck 기반 `depends_on` (서비스 기동 순서 보장)

**Shadow Mode 미들웨어 (`app/middleware/shadow_mode.py`)**
- 5개 AI 게이트 경로 인터셉트
- 런타임 토글 (`SHADOW_MODE` env var), 감사 로깅
- X-Shadow-Mode / X-Approval-Required 응답 헤더

**Approval 워크플로우 (`app/api/approval_router.py`)**
- 4상태: PENDING / APPROVED / REJECTED / EXPIRED
- 24시간 자동만료 + 거절사유 필수 가드
- 역할 기반 승인 게이트 (FERMENTATION_CONDITION → MANAGER/ADMIN)

### 4. LOT 트레이서빌리티 (90%)

- **LOT 프리픽스 일관**: RM-(원재료) / SA-(절임) / FE-(발효) / PK-(포장) / SO-(출하주문) / CL-(클레임)
- **FK 체인**: `raw_material_lot` → `fermentation_lot.source_lot_id`(SA- 경유) → `packaging_lot.source_lot_id`(FE-) → `shipping_order_lot`
- 시드 데이터로 체인 검증됨 (다국 LOT ID 형식 YYYYMMDD-NNN 통일)
- **Gap**: 절임(SA-)은 독립 `salting_lot` 테이블이 아니라 `process_result` PROC03에 표현 → FK가 논리적 연결(VARCHAR source_lot_id)이며 DB 레벨 강제는 부분적

### 5. 기술 스택 준수 (100%)

- FastAPI 0.115 + asyncpg 0.29 + Pydantic 2.9 (async/await 일관, model_validator v2)
- Streamlit 1.39 + `@st.fragment(run_every=N)` + httpx + Plotly
- pgvector 0.3.2 + `embedding <=> query` 코사인 + ivfflat 인덱스 + text-embedding-3-small(1536)
- LangChain 0.3.7 / LangGraph 0.2.39 / XGBoost 2.1 / TensorFlow 2.17 / SHAP 0.46 전부 고정 버전
